# ADR-024: Резидентность и мультирегиональность для платформы данных и ML

## Контекст

Платформа данных и ML (ADR-019…ADR-023) должна соответствовать уже принятой модели развёртывания: **5 суб-регионов** в **3 макро-регионах** (`base`, `sea-sg`, `sea-id`, `sa-br`, `sa-cl`, ADR-013) с **резидентностью PII** (NFR-C-01) и **деидентифицированной глобальной аналитикой** (ADR-014, ADR-017).

Ключевое противоречие: **ML традиционно любит централизацию** (единый датасет, единое обучение), а **регуляторика требует изоляции** PII по регионам. Отдельно стоит вопрос: где обучать модели и как переносить их между регионами.

Ограничения:
- PII не покидает регион присутствия без правового основания (ADR-014, ADR-017);
- RPO ≤ 1 мин / RTO ≤ 15 мин - для критичных данных (NFR-A-04), но аналитика/ML - **не** критичный путь поездки;
- Косвенный слой: **агрегаты** деидентифицированы, а **артефакты моделей** не содержат PII напрямую (но требуют проверки на "запоминание" - см. риски);
- cost (FinOps) и операционная сложность мультирегиона.

## Требования

1. Данные (сырые данные, признаки, витрины) размещаются **per-region**; PII остаётся в регионе.
2. **Глобальный слой** аналитики - только **деидентифицированные/агрегированные** данные.
3. ML: обучение и инференс учитывают резидентность; модели могут обслуживаться во всех регионах.
4. **Единые определения признаков** и **единый реестр моделей** без дублирования логики.
5. Шифрование и управление доступом **per-region** (KMS/Vault/IAM, ADR-018).
6. Поддержка **прав субъектов** (DSR) и удаления данных в распределённой среде.
7. Отказоустойчивость и восстановление данных/ML в рамках согласованных RTO/RPO.

## Решение

### Топология: региональная платформа + глобальный деидентифицированный слой

| Слой | Размещение                  | Данные | Примечание |
|------|-----------------------------|--------|------------|
| **Ingest + bronze/silver** | per-region                  | Доменные события, PII в токенизированном виде | Региональная локальность, immutable bronze |
| **Feature offline/online** | per-region                  | Признаки (region-scoped) | Feast offline (Iceberg) + online (Redis) |
| **Serving (ClickHouse)** | per-region                  | Витрины gold | Региональный BI |
| **Model Serving (KServe)** | per-region                  | Артефакты моделей (не PII) | Инференс рядом с сервисами |
| **Experiment tracking / Registry (MLflow)** | Глобальный (или hub-регион) | Метаданные/артефакты моделей (не PII) | Единый реестр версий/стадий |
| **Global analytics (ClickHouse)** | Глобальный (hub)            | Деидентифицированные агрегаты | Кросс-региональный BI |
| **Feature definitions (repo)** | Глобальный (Git)            | Код/дефиниции | Единые определения, значения - региональные |

- **Обучение**: выполняется в регионе на **региональных** данных, либо на **глобальном деидентифицированном** датасете. Сырые PII между регионами не передаются.
- **Артефакты моделей (веса)** не содержат PII напрямую; после проверки на приватность (риск "запоминания") они реплицируются в реестр и во все регионы для инференса - это не нарушает резидентность.
- **Feature-инженерия** едина (feature repo), но **значения признаков** остаются региональными.

### Деидентификация перед выходом в глобальный слой

- Токенизация PII выполняется **на ingest (до записи в bronze)** per-subject токенами (ADR-020); перед любой кросс-региональной передачей данные дополнительно деидентифицируются (ADR-023); проверки-guardrails запрещают PII в глобальных таблицах.
- В глобальный слой идут только агрегаты и деидентифицированные события (например, обезличенные метрики спроса/предложения по зонам).

### Безопасность и управление

- **KMS per-region** - ключи шифрования at-rest для бакетов/БД/Redis региона (ADR-018).
- **Vault per-region** - секреты и доступ к хранилищам; **IAM/RBAC**, masked views.
- **mTLS** между компонентами данных и ML (service mesh, ADR-018).
- **Аудит** доступа к данным (кто/что/когда читал PII), интеграция с SIEM (ADR-018), retention ≥ 1 года.

### Права субъектов и удаление

- **Data map** (ADR-017) связывает субъекта с регионами хранения его данных.
- **DSR** (доступ/исправление/удаление/портируемость) маршрутизируется в регион субъекта; исполнитель затрагивает **все слои** (bronze/silver/gold/признаки) региона.
- **Удаление** реализуется **crypto-shreddingом**: поскольку PII токенизируется **per-subject** уже на ingest (ADR-020), удаление ключа субъекта делает его данные нераспознаваемыми во **всех** слоях, включая append-only bronze, **без перезаписи immutable-истории**. Физическое удаление из региональных слоёв применяется по регламенту retention к не-токенизированным остаткам.

### Отказоустойчивость данных и ML

- Аналитика/ML - **не** критичный путь поездки: при деградации ride-flow не страдает; допускается деградация свежести отчётов/инференса с fallback (бизнес-правила, ADR-021).
- **DR**: репликация Object Storage/bronze внутри макро-региона (ADR-014); восстановление silver/gold **пересборкой** из bronze (идемпотентно) - это снижает требования к репликации производных слоёв.
- Модели восстанавливаются из глобального реестра (артефакты не PII).

## Альтернативы

1. **Единая глобальная платформа данных/ML.** Просто для ML, но нарушает резидентность (152-ФЗ, UU PDP, LGPD) - неприемлемо.
2. **Полная изоляция по регионам, включая реестр моделей.** Максимальная изоляция, но дублирование реестра/логики и медленная синхронизация.
3. **Централизованное обучение на сырых PII.** Проще для дата-сайентистов, но недопустимо регуляторно.
4. **Federated learning.** Данные не покидают регион, обучение распределённое - перспективное, но существенно сложнее; не для первой итерации.
5. **Централизованный деидентифицированный датасет для всего.** Согласуется с (1) для агрегатов, но не решает региональные признаки/инференс.

## Компромиссы и риски

- **Дублирование инфраструктуры данных/ML** по регионам → рост стоимости; митигация - FinOps, автоскейл, пересборка слоёв из bronze вместо репликации.
- **Кросс-региональные отчёты запаздывают** (деидентифицированные агрегаты реплицируются асинхронно); принимается (eventual consistency, NFR-D-01).
- **Согласованность моделей между регионами**: одна версия модели во всех регионах через глобальный реестр; при региональных различиях - региональные варианты с общим контрактом.
- **Деидентификация**: необратимость и её достаточность требуют юридической валидации (ADR-017); слабая деидентификация = риск утечки.
- **DSR в распределённой среде** сложен (несколько регионов/слоёв); митигация - data map и автоматизация (ADR-017).
- **crypto-shredding** не удаляет физически, но делает данные непригодными; регламент и аудит обязательны.
- **Модели как потенциальный носитель PII**: модель, обученная на персональных данных, может "запоминать" их (риск membership/inversion-атак), поэтому артефакт модели **не считается автоматически обезличенным**. Митигация: обучение преимущественно на деидентифицированных данных, доступ к реестру и артефактам - по least privilege, проверки приватности для критичных моделей; глобальная репликация артефактов допускается только после такой проверки.
- **Операционная сложность** мультирегионального data/ML-стека; митигация - единый IaC/CI-CD и runbook.

## Допущения

- Глобальный hub-регион (реестр моделей, глобальная аналитика) определён и не хранит PII.
- Региональные провайдеры предоставляют KMS/Vault/Object Storage с нужными режимами.
- Правовые основания для регионального обучения и деидентификации подтверждаются комплаенс-командой (ADR-017).
- ML-инференс и аналитика допускают деградацию при региональных сбоях без влияния на ride-flow.
