# ADR-018: Средства защиты в ландшафте (WAF, Firewall, IDS/IPS, secrets, mTLS)

- **Автор:** Дмитрий Ренев
- **Статус:** На согласовании
- **Согласующие:** Дмитрий Бардин
- **Дата:** 2026-10-16
- **Связанные артефакты:** [ADR-013-deployment-regions.md](ADR-013-deployment-regions.md), [ADR-015-geo-routing.md](ADR-015-geo-routing.md), [ADR-017-compliance.md](ADR-017-compliance.md), [ADR-001-nfr.md](../../Task1/adr/ADR-001-nfr.md), [c2-to-be.puml](../diagrams/c2-to-be.puml)

## Контекст

Платформа разворачивается в **5 суб-регионах** трёх макро-регионов (ADR-013), обслуживает **PII и платежи**, подчиняется **локальным регуляторным 
требованиям** (ADR-017) и должна обеспечивать **99,99 %** (NFR-A-01). В систему нужно встроить **средства защиты** (WAF, Firewall и аналогичные) 
так, чтобы они были **регионально-распределёнными** и **не создавали единую точку отказа**.

Существующие НФТ по безопасности (ADR-001): zero-trust и mTLS между сервисами (NFR-SEC-01), защита периметра WAF/Firewall/rate limiting (NFR-SEC-02), Vault/Secret Manager и ротация ключей (NFR-SEC-03), соответствие PCI DSS (NFR-SEC-04).

## Требования

1. Добавить в систему защиты периметра: **WAF**, **DDoS/scrubbing**, **Firewall/L3-L4**, **rate limiting**, **bot-защита**.
2. Отразить **сетевую сегментацию** и **внутренние контроли**: firewall-политики, **service mesh с mTLS** (zero-trust), **IDS/IPS**.
3. Отразить **управление секретами и ключами** (Vault/Secret Manager, KMS per-region) и **шифрование**.
4. Отразить **защиту данных**: разграничение доступа, токенизацию/маскирование PII, шифрование at-rest.
5. Отразить **управление идентификацией** (IAM, SSO, OAuth2/OIDC, RBAC).
6. Отразить **безопасность рантайма/контейнеров** (скан образов, admission control) и **SIEM/аудит**.
7. Все средства - **регионально-распределённые** (без глобального SPOF) и согласованные с геомаршрутизацией (ADR-015).

### Добавленные средства защиты и обоснование

| Механизм | Где на C2 | Что защищает | Обоснование                                                                                                                                                              |
|----------|-----------|--------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **WAF** | Региональный edge-периметр (перед API Gateway) | HTTP(S)-атаки: OWASP Top-10, инъекции, скриптинг, абьюз API | Публичный вход (мобильные/веб) - основная поверхность атаки; WAF отсекает атаки до сервисов; размещён **в каждом регионе** (нет SPOF)                                    |
| **DDoS-защита / scrubbing** | Глобальный периметр + регион | Объёмные (L3/L4) и прикладные (L7) атаки | Совместно с anycast/Global LB (ADR-015) поглощает атаку и защищает доступность 99,99 %                                                                                   |
| **Firewall / security groups / NACL** | Сеть каждого региона | Несанкционированный сетевой доступ | Least-privilege сегментация: разделение edge, сервисов, данных, observability                                                                                            |
| **Rate limiting / квоты** | API Gateway + WAF | Перегрузка, brute force, абьюз | Защита от перегрузки и злоупотреблений; часть load shedding (ADR-016)                                                                                                    |
| **Bot-защита** | Edge-периметр | Автоматизированный абьюз (фрод, парсинг) | Для маркетплейса важно ограничивать скриптовый абьюз (фейковые поездки, накрутка)                                                                                        |
| **Service Mesh + mTLS (zero-trust)** | Между сервисами | Перехват/подмена межсервисного трафика | NFR-SEC-01: аутентификация и шифрование "сервис-сервис"; шифрование in-transit                                                                                           |
| **IDS/IPS** | Сеть региона / edge | Аномалии и известные атаки | Обнаружение вторжений и сетевых аномалий; питает SIEM                                                                                                                    |
| **Vault / Secret Manager** | Отдельно в каждом регионе | Секреты, ключи, токены | NFR-SEC-03: централизованное хранение и ротация; per-region для резидентности                                                                                            |
| **KMS (ключи per-region)** | Хранилища каждого региона | Данные at-rest | Шифрование данных ключами региона (резидентность, ADR-014/017)                                                                                                           |
| **IAM / SSO / OAuth2-OIDC / RBAC** | Платформенный слой | Доступ пользователей и операторов | Управление доступом, least privilege, аудит действий                                                                                                                     |
| **Токенизация/маскирование PII** | Платёжный путь и аналитика | Платёжные и персональные данные | PCI DSS (не хранить PAN), комплаенс (ADR-017), снижение риска утечки                                                                                                     |
| **Скан образов + admission control** | CI/CD и кластер | Уязвимые образы в рантайме | Supply-chain безопасность: проверка образов до деплоя                                                                                                                    |
| **SIEM** | Observability / Security | Обнаружение событий безопасности, корреляция, расследование инцидентов | Обрабатывает события WAF/IDS/mesh/шлюза/сервисов; уведомление об инцидентах (ADR-017)                                                                                    |
| **Неизменяемый аудит-стор (WORM)** | Безопасность (per-region) | Доказательная база аудита | Требование аудита (NFR-C-03): append-only + Object Lock, retention ≥ 1 год. **Отдельно от Loki** (Loki - операционный поиск, не даёт immutability/длительного retention) |

### Принципы размещения

- **Региональная распределённость:** WAF, firewall, IDS/IPS, Vault, KMS, mesh - в каждом регионе; отказ одного не затрагивает другие.
- **Defense in depth:** защита на периметре (WAF/DDoS/rate limiting) → сегментация (firewall) → сервисный слой (mTLS/IDS) → данные (шифрование/токенизация/аудит).
- **Zero-trust:** ни один внутренний вызов не считается доверенным - mTLS и авторизация на каждом шаге.
- **Согласованность с геомаршрутизацией:** WAF и защита периметра стоят за Global LB (ADR-015); health-based failover не обходит защиту.
- **Наблюдаемость:** события безопасности идут в SIEM/audit (ADR-012).

### Изменения на диаграмме контейнеров

1. В границе **"Edge / Integration / Защита периметра"**: DDoS/scrubbing, WAF, bot-защита перед API Gateway (rate limiting - на шлюзе).
2. Добавлена отдельная граница **"Сетевая безопасность / Zero-trust"**: firewall-политики/сегментация (L3/L4), IDS/IPS, **Service Mesh с mTLS** (east-west). Уровни больше не смешиваются с периметром.
3. Добавлены **Vault/Secret Manager** и **KMS** (per-region) с шифрованием.
4. Добавлены **IAM/SSO**, **токенизация PII**.
5. Добавлены **скан образов/admission control**, **SIEM** (корреляция событий безопасности) и **отдельный неизменяемый аудит-стор** (Object Storage с WORM/Object Lock, append-only, retention ≥ 1 год). Loki при этом остаётся операционным агрегатором логов и **не** отвечает за неизменяемость аудита.

## Альтернативы

1. **Централизованный (единый) WAF/периметр.** Проще управление, но создаёт SPOF и не соответствует мультирегиону/резидентности.
2. **Только сетевой firewall без WAF.** Не защищает от прикладных атак (OWASP), недостаточно для публичного API.
3. **Без service mesh (только TLS на входе).** Внутренний east-west трафик не защищён, нарушает zero-trust.
4. **Хранение секретов в конфигурации/переменных окружения.** Небезопасно, нет ротации и аудита (нарушает NFR-SEC-03).
5. **Собственные сборки всех средств (self-hosted).** Больше контроля, но выше операционная нагрузка; managed-сервисы предпочтительнее (cloud-agnostic примитивы).

## Компромиссы и риски

- **WAF/mTLS добавляют задержку** (единицы–десятки мс); баланс с NFR-P-02 достигается размещением на edge и оптимизацией правил.
- **Ложные срабатывания WAF/IDS** могут блокировать легитимный трафик; митигация - tuned-правила, режим мониторинга перед блокировкой.
- **Service mesh усложняет эксплуатацию** (sidecar/прокси, mTLS-сертификаты); митигация - автоматизация выдачи сертификатов, стандартизация.
- **Per-region секреты/ключи** усложняют управление и ротацию; митигация - автоматизация ротации, единые политики.
- **Стоимость** средств защиты и трафика - FinOps.
- **Адmission/скан образов** замедляют доставку; митигация - асинхронный скан и политика "блокировать только критичное".

## Допущения

- Провайдеры предлагают managed WAF/DDoS/KMS/secret manager, доступные в целевых локациях (cloud-agnostic).
- Управление идентификацией интегрируется с существующими клиентскими и корпоративными сценариями (SSO для портала/админки).
- Платёжные PAN не хранятся в GoFuture (токенизация на стороне PSP).
